Overview

/serve spawns plain-HTTP development servers on loopback (127.0.0.1), with live-reload via Server-Sent Events and optional Cloudflare-Tunnel-gated public previews at <subdomain>.princess-pi.dev. No local SSL — the edge handles TLS termination. Invoked as serve from any shell, !serve from inside Pi. There is no /serve command face: ADR 0004 is shell-first, and the Pi extension survives only for the part a shell cannot render — the live active-server widget (/serve --hide, --show, --emoji).

Cloudflare Publishing (--pub <subdomain>)

Opt-in via --pub. Publishes the server at <subdomain>.princess-pi.dev through Cloudflare Tunnel, gated by Cloudflare Access (email OTP). The .serve-acl file in the served directory controls the allow-list. Without --pub, the server runs local-loopback only. --as is a legacy alias that still works — prefer --pub in new usage.

Republishing: Running serve <dir> --pub <new-subdomain> on an already-served directory publishes the new subdomain to the existing port — no new process spawned. Subdomain→port mappings persist in ~/.config/princess-pi-packages/serve/subdomains.json so --list shows the public URL even for servers published after start.

See SPEC_SECURE_DYNAMIC_SERVE.html for the historical NGINX/OAuth design (superseded) and the Cloudflare migration context.

Live-Reload Architecture

1. Native HTTP File Server

  • Zero Dependencies: Built strictly using Node.js standard library modules (node:http, node:fs, node:path, custom MIME mappings).
  • Cache Control: Sets headers to strictly bypass browser caches (Cache-Control: no-store, no-cache, must-revalidate) to prevent sticky dev states.
  • Client Script Injection: Automatically intercepts outgoing .html file read streams to inject a tiny native SSE listener script before the closing </body> tag.

2. Lightweight Live-Reload Protocol (SSE)

  • Server-Sent Events: Avoids external WebSocket packages. Exposes a special endpoint (/__live-reload) using standard HTTP protocols.
  • Auto-Reconnections: Browsers natively support reconnecting to SSE streams via the built-in EventSource API.

3. FS Watcher & Debounce Queue

  • Native Watching: Uses Node's native fs.watch (recursive) to monitor directory modifications.
  • Debounce Window: Groups rapid file changes into a single batched event (default: 150ms cooldown).

4. Dynamic Dependency-Tracing Engine

The server builds an in-memory Dependency Graph on startup and updates it dynamically on file saves:

  • HTML Scans: Maps <link rel="stylesheet">, <script src="...">, and fetch(...) endpoints.
  • JS Scans: Tracks static and dynamic import statements.
  • CSS Hot-Swap: CSS changes trigger targeted DOM updates with zero page reload.
  • JS/HTML Reload: Changes to imported modules trigger page reload; unused file changes are suppressed.

The Injected SSE Client Script

<script>
  (function() {
    const es = new EventSource('/__live-reload');
    es.onmessage = (e) => {
      const data = JSON.parse(e.data);
      if (data.type === 'css') {
        const links = document.querySelectorAll('link[rel="stylesheet"]');
        for (const link of links) {
          const url = new URL(link.href, window.location.href);
          if (url.pathname === data.path || url.pathname.endsWith(data.path)) {
            link.href = url.pathname + '?t=' + Date.now();
            break;
          }
        }
      } else if (data.type === 'reload') {
        location.reload();
      }
    };
  })();
</script>

Server Discovery & Lifecycle

  • Discovery: Scans ps aux for http-server and run-live-server processes. Reads --subdomain from process cmdline and ~/.config/princess-pi-packages/serve/subdomains.json for subdomains published after start.
  • Kill: --kill <port|dir|all> sends SIGKILL via captured PID. Unpublishes Cloudflare ingress rules and Access apps. Cleans subdomain map.
  • Orphan Reap: On every serve invocation, queries Cloudflare for tunnel ingress rules with no matching local process and removes them. Also cleans the local subdomain→port map and any stale advisory lock from a crashed publish.
  • Session Shutdown: On Pi /quit, prints a table of active servers as a reminder. Servers remain running across sessions.

Static Fallback (--static / -s)

Spawns npx http-server instead of the native live-reload server. No code injection, cache-busting, or file watching. Useful for testing production builds locally.

CLI Mode (Outside Pi)

bin/serve.mjs is a standalone, Pi-independent port built with Bun. It reuses the same extensions/lib/serve/ modules. Installed globally via:

npm install -g github:duppypro/princess-pi-packages
  • Supported: [dirs...], --static/-s, --list/-L, --kill/-k, --pub <subdomain>, --help/-h, --version, --why, --force/-f — identical behavior to the Pi extension.
  • Pi-only (accepted silently): --emoji/--no-emoji (terminal rendering hint).
  • Pi-only (notify): --show/-S, --hide/-H — no TUI widget in CLI.
  • CLI-only: --force/-f bypasses the .env secret warning (Pi prompts interactively instead).

Security

  • Loopback only: All servers bind to 127.0.0.1. Public access is gated exclusively through Cloudflare Tunnel → Access (email OTP).
  • .env detection: Scans target directories for .env files and prompts for confirmation before serving. CLI requires --force to proceed.
  • Access logging: Apache Common Log Format to ~/.config/princess-pi-packages/serve/logs/port-<PORT>-access.log. Auto-rotates at 5MB (capped at 10MB total per server).
  • No standing privilege: Cloudflare API token lives in ~/.config/princess-pi/cf.env (0600). No sudo, no NGINX reloads, no filesystem ACL maps.

Settings Persistence

Uses the shared extensions/lib/config.ts module. Config at ~/.config/princess-pi/serve.json (user-global) and ./.princess-pi/serve.json (project-local, overrides global).
